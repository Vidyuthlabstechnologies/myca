1. Sandbox by Quicko (GSTIN checks, returns, GSTR-2B job, TDS, e-invoice)

How to get the keys:

  1. Open developer.sandbox.co.in and sign up with your work email (free; the TEST plan needs no card).
  2. Verify the email, sign in, and open API keys in the left menu.
  3. Click Create key, name it MyCA test, and copy the API key and the API secret. The secret is shown once; if you lose it, create a new key.
  4. For sandbox testing keep the environment on Test; it talks to test-api.sandbox.co.in, which answers with fixture data and the same taxpayer for every GSTIN. Switch to Live only with a paid plan and a live key.
  5. Paste both below and click Save and test.

2. NIC e-invoice sandbox (IRN and e-way bill)

How to get the credentials:

  1. Open einv-apisandbox.nic.in and register with your GSTIN; choose User type: Tax Payer (not GSP).
  2. After the OTP sign-up, open API credentials: note the Client ID and Client Secret NIC issues for the sandbox.
  3. Create an API user (username and password) under the same menu; this is different from the portal login.
  4. Download the sandbox public key (.cer) from the same page; MyCA uses it to encrypt the session key. Paste its PEM text below or leave it for later.
  5. Paste everything below and click Save. The live NIC portal needs separate production onboarding; keep this on Sandbox.

3. What a sandbox test needs besides the keys

Sandbox calls leave this PC only when the live switch is on: set MYCA_ENABLE_LIVE_CALLS=1 and MYCA_MOCK_MODE=0 in platform/.env and restart MyCA. With the switch off, every call is recorded as a dry run and nothing is sent, which is the safe default. Writes (saving or filing a return, generating an IRN) also need a CA approval; reads (GSTIN checks, status, reconciliation jobs) do not.
